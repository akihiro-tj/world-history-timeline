# 国・地域で見る表示 設計書

- 作成日: 2026-09-28
- 状態: 承認待ち
- 前提: [2026-09-27-world-history-timeline-design.md](./2026-09-27-world-history-timeline-design.md)（以下「MVP の spec」）

## 1. 目的

MVP では、主題（王朝／王）を 1 つ選ぶと、行＝国・地域でその主題の棒が並ぶ。これに加えて、国・地域を 1 つ選ぶと、その国・地域の王朝と王が同じ時間軸に並ぶ表示を足す。

ねらい:

- **王朝と王の対応を読み取れる**: 王朝の行と王の行を隣り合わせに置き、どの王がどの王朝の時代かを棒の位置の重なりから読み取れるようにする
- **主題を増やすときの土台**: 将来、戦争・教皇などの主題が増えたら、国・地域の表示の行が増える。「その国・地域の出来事をまとめて見る」画面になる

成功の基準:

- 表示 4 通り（王朝・王・フランク王国・フランス・イングランド）× 向き 2 通りのすべてで、MVP のデータが欠けや重なりなく表示される
- PC 幅と 375px 幅の実ブラウザで、ヘッダーが 1 段に収まり、表示の切り替えが問題なく動く
- 表示や向きを切り替えても、見ていた年のあたりが表示され続ける

## 2. スコープ

### 含めるもの

- 表示のセレクトに「国・地域」の群を足し、国・地域を選ぶと、その行の王朝と王を 2 行で並べる

### 含めないもの

- データの変更。在位 → 王朝の関係（MVP の spec §4.1）は足さない。王の棒を王朝ごとに色分けする・囲むなど、所属をはっきり見せるのは、必要になったら別の変更で行う
- data リポと成果物（`timeline.json`）の形の変更
- 国・地域ごとに年の範囲を詰めること
- 表示の状態を URL に持つこと

## 3. 画面と操作

### 3.1 表示のセレクト

MVP の主題のセレクトを、表示のセレクトにする。選択肢を見出し付きの 2 群（ネイティブの `optgroup`）に分ける。

| 群の見出し | 選択肢 | 選んだときの年表 |
|---|---|---|
| 主題 | 王朝 ／ 王 | MVP と同じ。行＝国・地域 |
| 国・地域 | データの行の名前（配列の順）。MVP のデータでは フランク王国・フランス ／ イングランド | 行＝王朝・王（§3.2） |

- 主題と国・地域をひとつのセレクトにまとめるのは、ヘッダーを 375px 幅でも 1 段に保ち、主題や国・地域が増えても選択肢が増えるだけで済むようにするため（MVP の spec §3 の「数によらず 1 段に収まるセレクト」の方針のまま）
- 起動時は「王朝」を選んだ状態（MVP と同じ）
- 年表のデータを読み込むまでは、国・地域の群を出さない（主題の群だけ）
- 向きの切り替えは MVP のまま

検討して採らなかった案:

- 「主題／国」を切り替えるボタンと、中身が入れ替わるセレクトの 2 段: 操作が 2 段階になり、375px 幅でヘッダーが 2 段に折り返す
- 年表の行の名前をタップしてその国・地域に入り、「戻る」で出る: 押せることに気づきにくく、別の国・地域へ直接移れない

### 3.2 国・地域を選んだときの年表

- 行は上から「王朝」「王」の 2 行（縦向きなら 2 列）。中身は、選んだ行（`lanes[]`）の `dynasties` と `reigns`
- 行の名前は、主題の選択肢の文言「王朝」「王」を使う
- 棒の出し方（名前と期間、段分け、棒の外に出すラベル、交互の色）は MVP の spec §3.1 のまま
- 在位の中には、どの王朝の棒とも重ならないもの（MVP のデータではエグバート、アルフレッド大王）がある。そのまま出す

### 3.3 年の範囲とスクロール

- 年の範囲は、どの表示でもデータ全体（MVP の spec §3.1 のまま）。表示を切り替えても中央の年を保てるようにするため。国・地域を選ぶと、その国・地域のデータがない時期は空白になる
- 表示や向きを切り替えたら、切り替え前に画面中央にあった年を中央に置く（MVP の spec §3.2 のまま）

## 4. 作り

### 4.1 表示の状態

```ts
type View = { kind: "subject"; subject: Subject } | { kind: "lane"; laneId: string };
```

- App は MVP の `subject` の代わりに `View` を持つ。初期値は `{ kind: "subject", subject: "dynasty" }`
- セレクトの値は文字列（`subject:dynasty`、`lane:england` など）。`View` との相互変換は純粋関数にする。知らない値は無視する（変換の結果を `null` にし、状態を変えない）

### 4.2 変える単位

| ファイル | 変更 |
|---|---|
| `src/timeline/spans.ts` | `rowsForView(data, view, names)` を足す。年表の行 `{ id: string; name: string; spans: Span[] }[]` を返す。主題の表示では `spansForLane` で行＝国・地域を作り、国・地域の表示では行＝王朝・王を作る（行の名前は引数 `names` で受け取る。App が `COPY` から渡す）。存在しない `laneId` なら例外にする。`View` の型とセレクトの値との変換もここに置く |
| `src/timeline/Timeline.tsx` | `data` と `subject` の代わりに、行（`rowsForView` の結果）と年の範囲を受け取る。描画・段分け・中央の年を保つ処理は変えない |
| `src/app/SubjectSelect.tsx` → `src/app/ViewSelect.tsx` | 見出し付きの群（`optgroup`）を受け取る |
| `src/app/App.tsx` | 表示の状態を持ち、選択肢を「主題」と「国・地域」（`data.lanes` から作る）の 2 群で組む。年の範囲は MVP と同じく `timeRange(data)` |
| `src/app/copy.ts` | §5 の文言 |

- データの型と検証（`src/data/timeline.ts`）、成果物、data リポは変えない
- DESIGN.md は、Layout と Components の「主題のセレクト」の説明を「表示のセレクト」に直す。トークンの名前 `subject-select` は、生成する CSS に影響するので変えない

## 5. UI 文言

MVP の spec §6 から変える・足すものだけ。

| 場所 | 文言 |
|---|---|
| 表示のセレクトの `aria-label` | 表示（MVP の「主題」から変える） |
| 選択肢の群の見出し | 主題 ／ 国・地域 |
| 国・地域の表示の行の名前 | 王朝 ／ 王（主題の選択肢と同じ文言） |

## 6. 検証

- Vitest: `rowsForView`（主題の表示 2 通り、国・地域の表示、存在しない `laneId`）、セレクトの値と `View` の相互変換（知らない値を含む）
- 実ブラウザ（headless Chromium）: PC 幅と 375px 幅のそれぞれで、表示 4 通り × 向き 2 通りを確かめる。表示を切り替えたときに中央の年が保たれること、375px 幅でヘッダーが 1 段に収まることも確かめる
